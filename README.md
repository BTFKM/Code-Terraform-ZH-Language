# Code Terraform 中文补丁

本补丁为《Code: Terraform》正式版（非 Demo）提供简体中文界面汉化。

> ## ⚠️ 作者更新过于频繁，token 扛不住了，不能更新了家人们 🙏
>
> 本补丁当前适配 **最新版（2026-09-15 更新 / buildid 25296639）**，之后的版本不保证继续跟进。
> 但补丁器本身是通用的、不写死版本：新版上自己重跑一遍就能打上——
>
> ```bash
> python ctzh.py                 # 自动发现新版资产表与字典宿主，重新求解并打补丁(纯本地计算，无网络)
> python ctzh.py --extract-only  # 导出新版全部原文与 key，对比 language.json 补译新增/改写条目后再重跑
> ```
>
> 新增文本自己补译（或机翻）后记得**先合进 `language.json` 再重跑**，否则解算缓存会因译文变化而重算。
> 欢迎 fork / 提 PR 接力维护，也欢迎在 issue 里贴出新版本的适配结果。
>
> **v1.3**：合并社区 PR #1（@Marsxxxxxxxx）的求解器优化——现版本改译或游戏更新后，
> 解算阶段从原来的 10~60 分钟降到**以秒计**（本机 28 线程实测 5.5 秒，详见更新日志），仍为纯本地计算、零位移。

> **现状说明**：译文字句来自机器翻译（经术语表约束与占位符校验），**未经人工逐条审校**，
> 可能存在误译、生硬或不一致；游戏内也可能存在字典之外的英文文本。
> 本补丁定位是"可用的中文汉化"，而非成品官方翻译——欢迎按下方方法自行修订润色，
> 欢迎提交 issue/PR 修正错译。

## 快速使用

### 方法一：脚本一键应用（推荐）

假设你已克隆本仓库到本地：

```bash
cd Code-Terraform-ZH-Language
python ctzh.py
```

脚本会：
1. 自动找到 Steam 库中的 `code-terraform.exe`（或 `--exe <路径>` 手动指定）
2. 解析 PE 重定位表，发现内嵌资产表（853~869 项，随版本变化）
3. 定位 6 个文本宿主 bundle：5 个字典副本（simWorker / editorAutocomplete / editorAnalysisWorker / persistenceCodecWorker / trainingExecutionWorker）+ 1 个 API 文档注册表（apiRegistry）
4. 注入 `language.json`（11648 条，全部已译）
5. 逐宿主求解压补偿并做零位移重打包（备份原版到 `code-terraform.exe.bak`，大小一字节不差）
6. 每个宿主的压缩结果都经解压回读校验，全部通过才写盘

预计耗时：大头是扫描/解析字典（约 5~15 分钟，与磁盘和 CPU 单核性能有关）。解算阶段：
原版 exe + 原版 `language.json` 直接命中磁盘缓存，秒级完成；改过译文或游戏更新后现场求解，
默认走 Brotli 元数据填充，**以秒计**（本机 28 逻辑线程实测 6 宿主合计 5.5 秒）。纯本地计算，无网络请求。

可选参数：

```bash
python ctzh.py --workers 32        # 压缩线程上限（默认=全部逻辑线程；扫描解析仍是单线程）
python ctzh.py --cache-only        # 只求解并缓存、不写游戏；之后去掉该参数一键应用
python ctzh.py --method search     # 强制传统随机注释搜索（兼容性对照/快速方式不可用时）
python ctzh.py --cache-dir DIR     # 自定义求解缓存目录（默认脚本旁 solutions/v2/）
```

每个宿主的解算结果成功一个就原子写入 `solutions/v2/`（按内容 SHA-256 寻址 + 完整性校验），
中断/失败后重跑不重做已完成项；换译文、换游戏版本自动隔离，不会误用旧结果。
`solutions/*.json`（v1.0~v1.2 的预计算参数）保留作为传统搜索的提示，不再新增写入。

### 方法二：手动编辑翻译后重新打包

如果你想自己润色某些句子，或补充官方新出的更新内容：

1. 编辑 `language.json`（JSON 数组，每条 `{"id":<索引>,"key":"<路径>","category":"<类别>","en":"<英文原文>","zh":"<译文>"}`）
   - `key` 是字典路径，如 `"menu.new_game"`、`"briefing.day001.m1"`、`"api.api_object_types.battery.level.description"`
   - `zh` 为中文，空字符串表示不翻译该条
   - 占位符 `{xxx}` 必须保留，不能增删（脚本校验，不合规条目自动跳过）
   - `en` 是补丁录制该行时的英文原文；游戏更新后若原文变化，脚本会自动跳过该条旧译文（防止错配），此时请更新 `en` + `zh` 再重跑
2. 重新打包（自动以 `.bak` 原版为基线，可反复重跑）：
```bash
python ctzh.py
```

想看当前版本的全部英文原文与 key：

```bash
python ctzh.py --extract-only   # 生成 leaves.json
```

## 回滚

若需恢复原版：
```bash
python ctzh.py --restore
```
（等价于 `cp code-terraform.exe.bak code-terraform.exe`）

## 技术细节（供想自己魔改的人）

### 字典定位

正式版 i18n 字典被构建工具复制进 5 个独立 worker bundle（文件名带版本哈希，脚本按内容锚点自动发现）：
simWorker、editorAutocomplete、editorAnalysisWorker、persistenceCodecWorker、trainingExecutionWorker，各约 2~5.7MB。

5 份内容完全一致（键路径、英文原文、叶子索引），所以注入时按 key 替换，5 份同步更新。
另有独立的 API 文档注册表宿主（apiRegistry，扁平点分 key，如 `api.api_object_types.battery.level.description`），与字典键空间不重叠。

### 零位移重打包

Tauri 把前端资产用 brotli 压缩后嵌入 PE 的 `.rdata` 节，资产表在重定位表里（指针 + 长度）。

若改变压缩后大小，需：
1. 更新资产表的 `data_len` 字段
2. 移动后续资产数据（导致指针全要改）
3. 更新 `.reloc` 重定位块
4. 重新签名 Authenticode（若有）

本方案：让压缩后大小恰好等于原始 `data_len`，所有指针保持不变，零位移，PE 结构完好。

**默认方法（metadata 填充，v1.3 起）**：流式压缩 `翻译后 JS` 并 FLUSH 到字节边界，然后按
[RFC 7932 §9.2](https://www.rfc-editor.org/rfc/rfc7932.html#section-9.2) 插入恰好填满剩余间隙的
元数据块（MSKIP，零载荷，不产生任何解压内容），再以空最后块收尾。只要目标尺寸 ≥ 基础压缩尺寸
就能一步到位，每个 quality 只需一次压缩——无需试算，解压结果仍是完整的已注入 JS。
依次尝试 quality 4/6/9/10/11；编码器收尾行为不符合假设或间隙不足时自动回退。

**兜底方法（随机注释搜索）**：JS 内容 = `翻译后 JS` + 换行 `/*随机字符 pad*/`（注释对解析器无害，
brotli 视为高熵数据），按 quality 11→10→9 求解 R。v1.3 的改进：真实输入先压缩定基线，插值逼近后
局部密扫，多线程在途共享输入（brotli 原生绑定压缩时释放 GIL，免进程池复制）；若密集扫描仍被尺寸
抖动跳过，再换 PAD 内容相位补扫。

两种方法的最终 blob 都做三重校验：长度 == `data_len`、解压逐字节等于预期输入、磁盘缓存条目
SHA-256 一致，任何一项失败都不会写入游戏。

## 常见问题

**Q: Steam 验证完整性会覆盖补丁吗？**  
A: 会（游戏更新同理）。重新跑 `python ctzh.py` 即可，缓存命中时几分钟完成。

**Q: 游戏更新后怎么办？**  
A: 直接重跑脚本。若新版的字典/注册表结构仍可解析，脚本会：跳过英文被改写的旧译文（宁缺勿错）、对新增键保持英文、重新求解变化的宿主。要完整覆盖新增文本，用 `--extract-only` 对比 `language.json` 补译后重跑。

**Q: `.bak` 是旧版本的怎么办？**  
A: 脚本会检测 `.bak` 与当前 exe 的版本指纹，不一致就忽略它、用当前原版重建，不会拿旧版文件当基线。

**Q: 某些词翻译得不好，怎么改？**  
A: 方法二编辑 `language.json` 对应条目，改 `zh` 字段后重新打包。

**Q: 能不能只汉化 UI 不汉化剧情？**  
A: 可以。编辑 `language.json`，删除或清空剧情类 key（如 `"briefing.*"`, `"transmissions.*"`, `"endgame.*"`）的 `zh` 字段。

**Q: 支持 Mac/Linux 版吗？**  
A: 本补丁为 Windows x64 PE。Mac/Linux 的 Tauri 产物结构不同（Mach-O / ELF，资产表发现逻辑要改），需另写。

**Q: 运行一次要多久？**  
A: v1.3 起解算本身以秒计（默认 Brotli 元数据填充，一次压缩即命中目标尺寸）。总耗时主要花在扫描解析：原版命中缓存时几分钟内；改译或更新后现场求解也只多几秒解算时间。若机器较慢，可先 `--cache-only` 预热，再一键应用。
